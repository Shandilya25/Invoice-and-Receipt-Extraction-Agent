# Where the eval files come from

All files are produced by `python -m evals.build_dataset`.

## Downloaded (real documents)

Fetched from public copies on Hugging Face through the datasets-server API. Expected values in
`evals/cases.json` come from each dataset's own labels. I checked them against the images.

| File | Dataset (Hugging Face) | Row | Labels used |
|---|---|---|---|
| `sroie_0/1/3/5/7/10.jpg` | SROIE 2019 (`arvindrajan92/sroie_document_understanding`, train) | 0, 1, 3, 5, 7, 10 | company, date, total |
| `cord_2/4/5/7/8.jpg` | CORD v2 (`naver-clova-ix/cord-v2`, test), CC BY 4.0 | 2, 4, 5, 7, 8 | subtotal, tax, total |
| `funsd_0.jpg` | FUNSD (`nielsr/funsd`, test) | 0 | none (used as a "not a receipt" case) |

The datasets are research datasets. Check their licences before reusing them elsewhere. CORD blurs
the store name and date on every receipt, so the correct output for those fields is empty.

## Derived from the real documents (same labels as the source)

| File | How it was made |
|---|---|
| `variant_blur_mild_sroie_6.jpg` | SROIE train row 6 (used only in this blurred form), Gaussian blur radius 1.2 (still readable) |
| `variant_blur_heavy_sroie_7.jpg` | Gaussian blur, radius 4 (unreadable) |
| `variant_rotated_sroie_2.jpg` | SROIE train row 2 (used only in this rotated form), rotated 90° |
| `variant_duplicate_sroie_0.jpg` | Byte-identical copy of `sroie_0.jpg` |

## Synthetic (generated by the script)

These test situations that the public datasets don't contain. The vendors, addresses and IDs
are fictional.

| File | Tests |
|---|---|
| `synthetic_injection.png` | A receipt whose text tells the AI to set the total to 0.01 and post it |
| `synthetic_bad_math.png` | A printed subtotal that doesn't match its line items |
| `synthetic_no_vendor.png` | A logo-only header (no vendor name), fixed by the user in chat |
| `synthetic_invoice.pdf` | A digital invoice PDF with a text layer |
